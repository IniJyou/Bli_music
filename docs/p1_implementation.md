# P1 基础播放器

初始实现：2026-10-30；搜索界面改版：2026-10-31。用户授权本阶段开发及所需下载；Git 提交、推送仍需另行授权。

## 行为与边界

- 顶部统一输入框接受关键词、BV / AV 编号、标准链接、b23.tv 短链和包含链接的分享文本。
- 搜索显示 B站视频结果，支持分页，最多读取接口提供的 50 页。标题中的 HTML 高亮转为纯文本。
- 关键词结果可直接播放、加入第一分段，或打开分段选择。BV / AV、标准链接与短链解析后也进入同一主区域列表；精确视频结果的播放、加入队列和分段选择均保留 `p=` 指定分段，未指定时使用 P1，可在分段侧栏多选或全选。
- 队列按 `bvid:cid` 去重，最多 500 首，支持跨视频、上下移动、移除及二次确认清空。
- 曲目名称由独立规则派生：分 P 只有“日语版／英语版／伴奏”等完整版本标签时，以视频原始标题作主名称，副行显示版本；有具体歌名时使用该分 P 歌名。空白、P1、数字等占位名回退视频标题。队列、底部播放器、聆听与沉浸页使用相同规则，悬停可查看完整名称；原始标题、分 P 标题和 `bvid:cid` 分别保留。
- 加入、搜索、分页或失败导入均不重建当前音频。播放所选才切换；删除当前曲目会停止播放并选择相邻曲目，等待用户继续。
- 顺序播放在末尾停止；列表循环、单曲循环、随机播放可通过播放按钮左侧图标切换。随机模式的上一首返回实际播放历史。
- 自然播放结束自动前进。自动续播遇到错误会标记并跳过，每轮最多尝试每首一次；全部失败后停止，仍可重试、移除或加入新曲。手动选择失败时保留明确错误，不悄悄换歌。
- 空格在非输入控件上切换播放；Esc 依次关闭对话框、侧栏或退出沉浸模式。
- 音量常驻显示百分比，可直接输入，Enter 或移开焦点确认，Esc 取消编辑；支持 0.1% 精度。滑杆加长并把更多行程分配给低音量，方向键微调 0.1%，Shift + 方向键调节 1%。音量百分比仍对应原来的实际增益，不改变同一数值的声音大小。
- 当前每次启动默认音量为 5%，界面、音频元素的初始增益和首次播放一致；尚未调过音量时，静音后恢复为 5%。首页已移除“试着听听”与两个示例入口。
- 静音后恢复最后一次非零音量，包括 0.1% 等小音量；切歌保持精确数值，不再固定恢复到 65%。
- 当前队列仅在内存，重启后清空；资料库、历史、断点恢复属于 P2，歌词属于 P3。

## 搜索界面与文字

按用户放在 `建议/搜素栏.png`、`建议/搜素后.png` 的参考调整搜索体验，保留三套场景与主体歌名的视觉层级。参考图仅用于理解布局，不作为应用素材；该文件夹已排除在 Git 范围外。

- 搜索框为 264–300px 宽、36px 高的轻量圆角样式，左侧搜索、右侧清空，输入与提示为 14px 常规字重；导航也采用适度字重，避免整栏粗大。
- 搜索结果使用主内容区的列表页面，按序号、标题、UP 主、时长与操作对齐，支持滚动与分页。实际提供的是视频音源，UP 主不会显示为歌手，也不填充不存在的专辑信息。
- 精确视频输入显示一条真实视频结果；多分段时显示总段数、当前 P 编号和分段名，时长对应当前分段。只在点击“选择分段”时打开分段侧栏；精确结果不显示无意义的搜索分页。最近搜索重新打开 BV / AV 或链接时仍按视频解析。
- 点击结果选择，双击标题或使用播放按钮开始聆听；顶部可播放所选或加入队列，行尾可加入队列与选择分段。搜索与选择不改变当前音频，播放动作才切歌。
- 点击“搜索”导航可返回保留的结果；顶部返回按钮回到聆听。搜索页面可进入沉浸播放，退出后回到原搜索页面。播放队列现为独立主页面，分段选择继续使用辅助侧栏。
- 下拉显示当前搜索动作与本次成功搜索过的词，最多保存 8 条、显示 5 条匹配历史，支持方向键、Enter、Esc 与清空输入。每条历史右侧的叉号可删除，顶部“清空历史”删除全部；这些操作保留当前输入、搜索结果与播放。键盘选择历史后可用 Delete 删除，或左右切换搜索／删除操作。它没有访问联想词接口，不将本地历史冒充热门推荐；重启后清空。中文输入法的组合确认不会提前发起搜索。
- 列表标题 15px，UP 主与时长 13px，辅助信息至少 12px；使用常规字重及轻量关键词高亮。其他页面保持已改善的字号与对比度。短窗口保留真实列表滚动空间，固定操作不被挤出。
- 版本标签在副行优先显示，主标题较长时仍可区分不同版本；队列同时显示 P 编号。规则按整个分 P 标签匹配，含“英语版”等词的具体歌名继续显示原歌名；复杂自定义命名暂按原分 P 标题展示。
- 沿用 Segoe UI 与微软雅黑 UI 等本机字体，无新增依赖、字体下载或外部素材请求。

新版截图与完整回归仍在 `.artifacts/p1`，包括 `search-results.png`、`search-results-900.png`、`search-suggestions.png`、`direct-bv-result.png`、`direct-bv-result-900.png` 和 `direct-multi-result.png`；本次改版前截图在 `.artifacts/search-redesign/before`。此前字号调整的截图、字体诊断与离线关于窗口检查在 `.artifacts/readability`，只作为对应改动的历史证据。

## 播放队列界面

按 `建议/播放队列.png` 的完整曲目列表调整，替代原来的窄侧栏。参考图片只用于布局理解，仍排除在 Git 与应用资源之外。

- 导航“播放队列”进入主区域表格，按序号、标题、UP 主、时长与操作对齐。纸感半透明底色延续场景，唱片图形用原创 CSS 绘制，无人物和外部图片请求。
- 标题 15px 常规字重、UP 主与时长 13px；副行以 12px 显示版本、P 编号与真实来源。正在播放的行显示音符跳动与低饱和高亮。
- 单击选择，双击行或标题播放；序号按钮和顶部“播放所选”也可播放。行尾上移、下移与移除在悬停或键盘聚焦时显示；触屏环境常显。
- “定位当前”选中并滚动到当前曲目，保持音源与进度。“添加音乐”进入搜索；清空先确认，取消保留队列与播放。
- 从聆听或搜索进入队列后，返回按钮与 Esc 回到原页面。队列进入沉浸后退出仍回队列，同一音频元素持续使用。分段加入后直接显示队列，“已加入”提示位于队列标题下。
- 900×680、1280×860、1440×960 检查固定操作、播放器与列表滚动空间。截图为 `.artifacts/p1/queue-results-900.png`、`queue-results-1280.png`、`queue-results-1440.png`、`queue-clear-confirm-900.png` 和 `queue-empty.png`。

## 网络与隔离

元信息、搜索通过 Electron 独立内存会话请求。搜索使用 B站公开 `/x/frontend/finger/spi` 返回的匿名 `buvid3`，仅保留本次进程内存，只允许校验后的单个设备字段；不接受个人 Cookie、不带 SESSDATA、不导入浏览器会话。不承诺所有网络环境均可搜索或播放，412 等限制仍明确显示。

实测 Electron 45.1.0 的 `session.fetch(..., { redirect: 'manual' })` 对 b23.tv 抛出 `Redirect was cancelled`。需要手动检查跳转的短链与音频 CDN 请求改用 Electron 自带 Node 的 fetch；它不使用浏览器 Cookie 容器。每次跳转都先核对域名、协议、端口和凭据，最终视频链接只解析，不任意跟随到其他主机。

IPC 继续限制可信主窗口及主框架，并检查搜索、分 P 和场景参数。音频地址仍为可过期的受控流引用，不保存为曲目身份。

## 最大化／还原与图标

用户报告的是 Windows 标题栏右上角最大化／还原。应用的沉浸聆听是页面切换，二者分别处理。

处理全窗口重绘成本与底色闪变：

1. 两层实时 SVG 噪声滤镜转换为本地生成的静态 PNG 纹理，保留纸感。
2. 调整窗口尺寸期间暂缓背景动画与场景过渡，尺寸稳定后恢复。
3. 原生窗口底色跟随当前场景，首次等待 `ready-to-show` 再显示；侧栏不再叠加实时背景模糊。
4. 默认保留硬件加速；另提供 `start-software.cmd`，只关闭本应用此次启动的硬件加速，供仍有整屏闪烁的设备对照。无需修改系统设置，也不保证适合所有显卡。

Electron [官方窗口说明](https://www.electronjs.org/docs/latest/api/browser-window)建议设置匹配的背景色并等待首次绘制；[官方窗口缩放分析](https://www.electronjs.org/blog/tech-talk-window-resize-behavior)也说明窗口重绘涉及 Chromium 与图形后端。上述处理针对已确认的应用因素；渲染帧验证不能证明物理显示器或驱动的整屏闪烁已消失。

咖啡杯为项目原创 SVG，使用纸白杯碟、深蓝底与长阴影；无人物、外部字体或下载素材。标题栏／任务栏使用 `resources/coffee.ico`（16 / 24 / 32 / 48 / 64 / 128 / 256），界面使用同源 SVG，预览 PNG 为 512。Windows 安装包及 exe 文件图标随 P5 打包验证。

`scripts/generate-assets.cjs` 仅通过已安装 Electron 离线渲染原创向量与纸纹。生成后的资源已在项目中，正常构建不需要运行生成脚本。

## 依赖与运行

沿用 P0 的 Electron、React、TypeScript、Vite 和 Node 内置测试。P1 没有下载或新增依赖，也没有引入 SQLite、歌词服务或外部图标库。缓存、运行资料及报告继续使用 D 盘项目内目录。现有依赖许可声明与 Electron notices 见 `p0_licenses.md`，当前锁文件核对见 `p1_dependency_licenses.json`；项目最终开源许可证仍待决定。

双击根目录 `start.cmd`，或使用 `node.exe scripts/run.mjs build` 后运行 `node.exe scripts/run.mjs start`。原 `start-p0.cmd` 保留为当前播放器的兼容入口。软件渲染用 `start-software.cmd`。启动脚本不会自动安装或更新依赖。

验证入口为 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build`、`npm.cmd run smoke:p1`。`smoke:p0` 保留为当前完整回归的别名；P0 的历史检查记录仍见原文档。新报告及截图保存在 `.artifacts/p1`。
