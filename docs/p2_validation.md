## 报告和隔离

逻辑测试使用 `.artifacts/p2/unit-*` 等独立目录；P1 桌面检查的数据位于对应 `.cache/runtime/smoke-*`。P2 每次生成一个新的 `.artifacts/p2/<时间戳-UUID>` 目录，三个进程只共享该次测试的资料库，不使用个人 `.data`。

总报告为 `.artifacts/p2/smoke-result.json`，指向当前通过批次。分进程报告是其 profile 目录内的 `write-result.json`、`restore-result.json`、`autoplay-result.json`。主要截图为 `library-900.png`、`library-1280.png`、`library-1440.png`、`library-edited-playing.png`、`library-backups.png` 与 `restart-paused.png`；搜索喜欢新增 `search-favorite-900.png`、`search-favorite-1280.png`、`search-favorite-part-playing.png`。

全部音频检查静音；自动播放进程在加载页面之前也由主进程关闭音频输出。真实接口与音轨没有注入样例；文件选择器通过测试专用路径完成，其后的 JSON 文件读写、解析、SQLite 备份与恢复全部真实执行。**Windows 原生文件选择框的鼠标／键盘操作尚未自动控制验证**。

开发期间实际遇到过一次 B站接口 NETWORK 超时。检查脚本对写入／手动恢复阶段允许通过普通播放按钮明确重试一次并计入报告；自动播放阶段不使用该重试。最终通过批次为 0 次重试，不代表接口永久稳定或所有内容可匿名播放。

## 用户体验步骤

1. 关闭原播放器后运行 `start.cmd`。搜索音乐，点击结果行的爱心，确认在“资料库 → 我喜欢”中出现，再点可取消；喜欢本身不加入队列或触发播放。关键词默认 P1，含 `p=2` 的视频链接应只喜欢 P2。
2. 在队列点“保存歌单”，新建或加入已有歌单；进入资料库检查喜欢、重命名、排序与歌单内搜索。
3. 编辑熟悉曲目的歌名和歌手，确认队列、底部及沉浸页名称一致，切换分 P 后版本对应。
4. 将进度跳到容易记的位置后关闭、重开。确认队列与进度恢复、音量 5%、默认安静；点击播放应继续该分 P。
5. 在“备份与设置”实际操作原生导出／导入文件窗口。默认路径在 D 盘，取消窗口应保留数据；导入时先看预览，再选择合并或恢复。
6. 可在自己的测试歌单上试删除和备份恢复。删除歌单保留曲目；“全部音乐”的删除会影响全部歌单、喜欢、历史与队列，界面会说明并自动备份。
7. 启动自动播放仅在确实想要时开启。实际声音、耳机、物理屏幕闪烁、长时间运行及系统文件窗口的体验仍以设备检查为准。

## 当前边界

- P1 没有持久队列可迁移，P2 的首次资料库从空状态开始。
- 原生文件窗口操作、磁盘实际断电／写满和损坏数据库的人工文件恢复未在个人环境破坏性演练；事务故障、回滚、原文件保护与备份读取已有自动化证据。
- 数据库不能打开时不自动覆盖，需要保留整个原目录后按实现文档恢复。备份当前展示最近 30 份，原文件保留在本机；安装包迁移仍属 P5。
- 首版跳过 P3 歌词与译文。网易云／QQ 外部歌单匹配和系统媒体功能安排在 P4，安装包安排在 P5。
