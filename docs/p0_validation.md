# P0 播放验证

日期：2026-10-30。状态：P0 开发与技术自动验证完成，用户真实设备试听尚未验收。所有自动音轨测试均为静音，未将自动解码成功写成用户已经听到声音。

## 验收范围

1. 无个人登录状态下解析 BV/AV 和完整视频链接。
2. 展示真实视频与分 P，选择一个不同于默认页的分 P。
3. 实际加载独立音轨，验证播放、暂停和跳转。
4. 验证音轨字节范围请求（Range）正确透传。
5. 视频失效、权限不足、请求受限或没有独立音轨时有明确错误。
6. 提供接口、许可记录与可运行的 Windows 演示。

## 实际 Electron 自动验证

命令为 `node.exe scripts/run.mjs build` 和 `node.exe scripts/run.mjs smoke`。Windows 沙箱限制了 Vite 的文件解析及 Electron 启动，在自动审批允许后于沙箱外运行；应用仍启用 `sandbox`、`contextIsolation` 和 `webSecurity`，没有为解决工具限制关闭应用安全设置。

验证结果包括：

1. 受隔离的界面没有 `window.require` 或 `window.process`，预加载桥正常。
2. 无个人账号状态下读取 10 个分 P，并通过界面选择 P2，CID 为 `275431`。
3. 多分 P 与单曲均有实际音频解码字节和递增的播放时间。
4. 通过界面进度条跳转到约 65 秒后可继续播放，并可通过按钮暂停。
5. 同一音轨请求 `bytes=4096-8191` 时返回 HTTP 206、4096 字节及正确 `Content-Range`。
6. 真实失效视频 `av1` 返回 `NOT_FOUND`，界面显示明确的失效信息。
7. UI 第一版新增检查：三种窗口尺寸无横向溢出且播放按钮可见；沉浸页与三种配色切换保留同一音频元素、地址与连续进度；暂停切页与音量控制、实际上一段/下一段播放、连接信息窗口与 Escape 返回均通过。界面截图及说明见 `ui_v1.md`。
8. 第二版扩展至 16 项：播放中展开与关闭真实分段列表不打断音频，最小窗口下列表不遮挡底部控制，Escape 关闭后焦点回到列表按钮；暂停时点击列表行可开始播放对应真实音轨。雨窗、漂流、日光与最终长歌名排版已截图检查，记录见 `ui_v2.md`。

当前截图位于 `.artifacts/ui-v2`，基础播放截图仍保存到 `.artifacts/p0/single-track.png`、`multi-page.png`；这些与测试报告属于本地产物，不随源码自动提交。音轨字节只用于流式播放与验证，没有导出音频文件。

实际通过项目启动器启动交互演示，并以 Windows 本地窗口信息确认初版 `Bli Music · P0` 可见；UI 改版后的窗口标题为 `Bli Music`。启动器已区分交互和自动检查：交互模式显示窗口，自动检查仍使用隐藏窗口。初次启动检查快照见 `.artifacts/p0/launcher-result.json`，第二版记录见 `ui_v2.md`。

真实地址过期重取及登录/付费受限视频尚无专门的实测样例；相关分支有逻辑测试，但不将其记作真实平台行为已验证。无 DASH 独立音轨的旧视频在 P0 明确提示暂不支持，不进行整段视频回退。

## 样例

- 单曲：`BV1GJ411x7h7`，初查为 1 个分 P。
- 多分 P：`BV17x411w7KC`，初查为 10 个分 P，演示选择 P2。
- 失效视频：`av1`，真实元信息检查已返回 `NOT_FOUND`，对应结果记录在元信息探测文件。
- 登录或访问限制：目前仅有错误映射测试数据，不宣称已有真实受限视频播放测试证据。

## 人工试听步骤

依赖经授权安装并通过构建后，运行 `start-p0.cmd`。

1. 点击“一首单曲”，读取后点击播放，确认有声音；试听后暂停。
2. 点击“一段合辑”，选择 P2，播放并确认内容确实切换。
3. 把进度拖到约 65 秒，确认能继续播放且进度正确。
4. 输入一个已失效的视频编号，确认显示具体错误而不是无响应。
5. 如果音轨连接失败，点击分段选择旁的刷新图标（“重新获取音源”）后再播放；记录发生问题的 BV、分 P 与错误码。
6. 播放时点击“沉浸聆听”，切换右下角雨窗、漂流、日光，再返回首页，确认声音没有中断；歌词功能准备中为当前实际状态。
7. 展开顶部“本次列表”，点击其他分段，确认内容切换；按 Escape 关闭列表后仍可使用底部播放器。

P0 不是安装包交付阶段。用户可根据熟悉的公开曲目再补充样例，暂不需要提供任何账号信息。
